# アルゴリズム名の付け方と語彙

振り返りで各問題に付ける名前の基準。目的は 3 つある。後で検索できること、類題と結びつくこと、
分野ごとの得手不得手を数えられること。そのために、表記を揃える。

## 付け方

1. **道具と型を分けて挙げる。** 道具は「何を使ったか」（データ構造・アルゴリズム）、型は
   「どう考えたか」（言い換え・典型テクニック）。難しい問題ほど、解けるかどうかを分けるのは
   型のほうなので、型を落とさない。
2. **粒度は「調べれば解説が見つかる名前」にする。** 「動的計画法」だけでは広すぎる。
   「動的計画法:桁DP」「動的計画法:区間DP」のように、`大分類:小分類` で一段細かくする。
3. **日本語の定着した呼び名を使う。** 下の語彙表にあるものはその表記に揃える。表にないものは、
   AtCoder の公式解説や AtCoder Problems で使われている呼び名を優先する。
4. **1 問あたり 1〜4 個。** 解法の中心にあるものだけ。入力を読んでソートしただけなら
   「ソート」は付けない。
5. **名前がない考察には、名前を作らない。** 「偶奇で場合分け」「答えの上界が小さいことに気づく」
   のように、やったことを短く書く。もっともらしい造語は検索できず、誤解のもとになる。
6. **A・B 問題は無理に付けない。** 「算術」「文字列操作」「シミュレーション」「全探索」程度でよい。
7. **同じものを指す名前が複数あるときは、道具の名前を 1 つ選ぶ。** 分野ごとに数えるとき、
   同じ解法が別々の名前に割れると傾向が見えなくなる。迷いやすい組は下の「寄せ先」に従う。

ヘッダーコメントにするときは、1 行に 1 つ、広い分類から具体的な手法の順に書く。補足は全角括弧で
添えてよい（例: `# 累積和 mod K（区間和が K の倍数 <=> 余りが等しい）`）。形式の基準は
`atcoder-ruby` の `references/idioms.md` にある。

## よくある付け間違い

- **「シミュレーション」で済ませる。** 手続きをそのまま回すだけなら正しいが、優先度付きキューや
  順序付き集合で手続きを高速化しているなら、その道具の名前を付ける。
- **使っただけのものを挙げる。** 入力を `tally` しただけで「連想配列」は付けない。解法の鍵に
  なっているときだけ付ける。
- **解説の言葉をそのまま借りる。** 解説が「これは○○の要領で解けます」と軽く触れているだけの
  名前を、本人のコードがそれを使っていないのに付けない。本人の解法と公式の解法は分けて書く。
- **同じものを別名で書く。** 上の「寄せ先」の表記に揃える。
